# 正式版与保留数据的升级

本仓库的正式版固定使用应用 ID `com.nailong.quiz.study`，对应此前生成的“奶龙刷题·内置题库”。开发版 `.dev` 仅供本地测试。

## 自动打包

所有分支先运行单元测试并编译 Release。只有 `main` 分支会继续执行 `signed-release`，使用原签名生成 `nailong-quiz-release-apk`。

每次正式构建的内部版本号为 `1000 + GITHUB_RUN_NUMBER`，高于初始安装包的 `11`，并随这个工作流的运行次数递增。不要随意重建或更换工作流文件来重置计数；迁移工作流时应确保新的版本号高于已发布版本。

正式打包需要两个 **Repository secrets**：

| 名称 | 内容 |
| --- | --- |
| `NAILONG_KEYSTORE_BASE64` | 原 `study-keystore.p12` 文件的 Base64 文本 |
| `NAILONG_STORE_PASSWORD` | 原密钥文件密码；也用于原来的同密码密钥项 |

原密钥别名为 `nailongstudy`。密钥保存在你单独留存的原始源码备份中，不能提交到公开仓库，也不能用新生成的密钥替代。

签名文件只在正式构建任务的临时目录中还原，打包结束后删除。私钥和密码不放入 APK 下载产物，公开配置中只保存签名证书的 SHA-256 指纹。

## 构建后的自动校验

`scripts/verify_release.py` 检查实际 APK 的签名证书与原签名一致、包名正确、版本号高于初始安装包、不是调试 APK、ZIP 对齐正常，并检查内置题库数量。信息写入同目录的 `release-info.json`。

`config/release-identity.json` 记录原应用的公开身份信息和数据库文件名；没有签名私钥。

## 数据保留规则

- 在已安装的内置题库版上直接安装正式更新 APK，选择更新。
- 保持正式版应用 ID、签名密钥、题库 ID、数据库文件名和已有题目 ID 稳定。
- 如需修改数据库结构，增加数据库版本并编写、测试数据迁移；不要使用清库重建作为升级方案。
- 本次仅调整构建、版本显示和签名校验，未更改现有数据库结构、文件名或题目 ID。

这些规则针对此前生成的内置题库版。最早的其他包名应用及 `.dev` 开发版各有自己的数据，不能自动并入正式版。
